# 十股股息基线的本机冻结与离线复算

基线使用旧看板 `d5d48c1` 的 `daily_update.py::income_replay` 与同一修订的 `data.json` 对照。归档闭包包括本机旧研究脚本中的静态本地 Python 导入，含包初始化文件、子模块和相对导入。看板文件来自 Git，旧研究脚本以实际归档摘要为身份，其历史 Git 修订无法核实。回放使用 Python 3.12 标准库及同版本的本机环境。

旧项目目录须包含 `strategy-dashboard` 的 Git checkout、其同级旧 Python 模块、`data/income`、`data/income_long` 和 `data/income_plan`。可选的原策略研究导出来自 `results/income/bank_selection/midea_replacement`。

```sh
python3.12 scripts/income_baseline.py freeze \
  --legacy-root "<简单回测目录>" \
  --snapshot "<仓库外私有目录>/income-baseline-v1"

python3.12 scripts/income_baseline.py replay \
  --snapshot "<仓库外私有目录>/income-baseline-v1" \
  --output "<仓库外私有目录>/income-baseline-v1-result.json"
```

每次冻结用全新目录。清单绑定源码、输入版本、环境、有效配置、各证券实际首尾行情和信号开始可用时点。历史参考、行情、账本和详细比较均留仓库外。复跑须使用与冻结源码一致的两个适配器文件，可从私有快照将两者复制到独立的私有运行目录。退出码 `0` 代表固定看板可用字段匹配，`1` 代表复算后发现对拍不符，`2` 表示输入、环境或执行错误。存在待裁决缺口时读取私有 `pending-gaps.json`。若旧模拟器能完成诊断复算，`pending-diagnostic.json` 会保存按原缺价规则计算的对拍和账本，并标为 `pending_decision`。有待裁决缺口的快照没有正式清单，`replay` 会拒绝。核对停牌证据或补采候选并经负责人裁决后另建输入版本。

## 输入和事件语义

- 在每只证券的首条有效行情之后，逐个 Session 核对原加载器实际接受的行情。无可用报价的 Session 按标的、日期记录待裁决缺口，区分预热与回测期影响。停牌身份需要证据，即使诊断复算与固定参考一致也仍须核对。
- 本机行情采用原腾讯未复权日线及 `sh000300` Session 日期轴，预热用早期行情，信号沿用新浪个股后复权因子。冻结保留原批次及字段。相关方法对应 a-stock-data 3.10.4 §1.2 与 §1.6。
- 已实施分红保留原值、状态、登记与除权日期及送转字段。按旧契约将原始 `PRETAX_BONUS_RMB` 由每 10 股人民币换成每股。旧模型在除权日开盘前按已有持股计入模拟余额，卖出按旧持有期限计税。旧模型没有实际到账日，因此历史现金优先与复投规则可能用到这部分模拟余额。冻结会检查批次冲突、登记/除权日期、因子事件一致性和必要预热，保留原按证券设定的开始限制。
- 如需核对候选补采，可按 a-stock-data 3.10.4 §4.4 将东财 `RPT_SHAREBONUS_DET` 的原始 JSON 保存为 `<带市场前缀的代码>.json`，并给 freeze 传入 `--candidates <私有候选目录>`。候选只筛选缺事件日期的实施记录，保留原始响应和字段，状态为待裁决。不得据通用辅助函数的单位注释直接变更旧派息账本。
- 原证券组合、50 万元初始资金、90/10 仓位、周股息率分位、KDJ、陕鼓动力价格区间、银行校准及 `cash_then_sell` 按旧路径执行。股息与税费复投规则由同一旧模拟器执行。固定历史组合及分红可用性未做 PIT 证明。

## 停牌核验

可在 `freeze` 时传入 `--suspension-evidence <私有 JSON>` 保存逐日停牌证据。文件的 `method` 为 `a-stock-data 3.10.4 §6.5`，`rows` 每项含 `code`、`date`、`baostock` 原始字段和对应的 `tencent`、`tdx` 记录或 `null`。BaoStock 须明确返回相同证券与日期且 `tradestatus=0`，有实际成交的记录产生冲突。每条证据必须对应实际检测到的缺价，证据 JSON 的 `sources` 必须列出原始文件相对于该 JSON 所在目录的路径和 SHA-256。冻结逐份校验并将原始文件复制到快照的 `suspension-sources/`，再由清单绑定派生记录和原始文件。冻结与离线回放均重新解析归档的 BaoStock 成功响应、腾讯日线及通达信沪市盘后包，逐证券及日期核对派生记录。缺少原始 BaoStock 行、派生与原始记录不一致或原始记录显示成交，均不接受为停牌。使用旧快照时可按其冻结适配器回放，原始字节校验从 schema v5 起生效，派生记录交叉核验从 schema v6 起生效。已核实停牌日继续跳过成交并沿用旧模型最近有效收盘估值。

本机核验以腾讯未复权日线和能够取得的通达信盘后包交叉检查。盘后包缺失或请求失败本身只能说明没有取到该包。BaoStock 状态缺失或成交证据冲突仍须保留为待裁决缺口。

## 历史余额口径

`legacy_book_balance` 是历史模型未投资账面余额，包含模型按除权日计入的股息。它只用于还原旧看板和核对权益。结果的 `settled_cash_available` 为 `null`，因为输入没有独立到账流水，无法区分已到账现金与应收。嵌套账本、校准划转及成交也使用 `legacy_income_balance`、`legacy_free_cash_used`、`modeled_transfer_amount` 和 `modeled_trade_cash_flow` 等模型字段。该结果不能用于可用资金判断。相同快照按其冻结适配器回放，当前适配器输出使用新版本口径。

## 验收对应

| 要求 | 证据 |
|---|---|
| 原组合、环境、配置、预热、版本 | 私有清单及固定源码副本 |
| 固定输入、冲突、预热不足及候选记录 | freeze、私有缺口记录、合成测试 |
| 停牌证据待裁决 | `pending-gaps.json` 按证券、日期、来源字段记录冲突影响及候选处理方式。缺少整条原始记录时字段为 `<来源>.record`；来源响应无法解析时为 `<来源>.response`。 |
| 来源校验及覆盖范围 | 原件缺失或链接异常记为 `<来源>.source`，摘要异常记为 `<来源>.digest`。按清单可定位的受影响日期记录，并汇总可读来源中的重复记录冲突。停牌证据阶段返回待裁决时，后续行情及账本检查尚未运行。 |
| 看板对拍 | 按日期精确匹配，NAV 和收益率绝对容差 `1e-7`，人民币绝对容差 `0.00500001`。比较逐日 NAV、净股息和可用汇总 |
| 研究导出对照 | 同策略同起点重叠区间的逐日值、校准日期及状态、可用费用和股息税。结果单独标记 |
| 逐笔费用与持仓 | 旧模拟器明细及独立逐日旧模型账面余额、持股市值与净值核对，人民币绝对容差 `1e-6`。历史参考缺逐笔成交和每日持股数量，固定看板版本也无逐日现金及持仓估值字段 |
