# 十股股息基线的本机冻结与离线复算

基线使用旧看板 `d5d48c1` 的 `daily_update.py::income_replay` 与同一修订的 `data.json` 对照。归档闭包包括本机旧研究脚本中的静态本地 Python 导入，含包初始化文件、子模块和相对导入。看板文件来自 Git，旧研究脚本以实际归档摘要为身份，其历史 Git 修订无法核实。回放使用 Python 3.12 标准库及同版本的本机环境。

旧项目目录须包含 `strategy-dashboard` 的 Git checkout、其同级旧 Python 模块、`data/income`、`data/income_long` 和 `data/income_plan`。可选的原策略研究导出来自 `results/income/bank_selection/midea_replacement`。

```sh
python3.12 scripts/income_baseline.py freeze \
  --legacy-root "<简单回测目录>" \
  --snapshot "<仓库外私有目录>/income-baseline-v1"

python3.12 scripts/income_baseline.py replay \
  --snapshot "<仓库外私有目录>/income-baseline-v1" \
  --output "<仓库外私有目录>/income-baseline-v1-result.json"
```

每次冻结用全新目录。清单绑定源码、输入版本、环境、有效配置、各证券实际首尾行情和信号开始可用时点。历史参考、行情、账本和详细比较均留仓库外。复跑须使用与冻结源码一致的两个适配器文件，可从私有快照将两者复制到独立的私有运行目录。退出码 `0` 代表固定看板可用字段匹配，`1` 代表复算后发现对拍不符，`2` 表示输入、环境或执行错误。存在待裁决缺口时读取私有 `pending-gaps.json`，处理后另建输入版本。

## 输入和事件语义

- 本机行情采用原腾讯未复权日线及 `sh000300` Session 日期轴，预热用早期行情，信号沿用新浪个股后复权因子。冻结保留原批次及字段。相关方法对应 a-stock-data 3.10.4 §1.2 与 §1.6。
- 已实施分红保留原值、状态、登记与除权日期及送转字段。按旧契约将原始 `PRETAX_BONUS_RMB` 由每 10 股人民币换成每股。旧模型在除权日开盘前按已有持股计入模拟余额，卖出按旧持有期限计税。旧模型没有实际到账日，因此历史现金优先与复投规则可能用到这部分模拟余额。冻结会检查批次冲突、登记/除权日期、因子事件一致性和必要预热，保留原按证券设定的开始限制。
- 如需核对候选补采，可按 a-stock-data 3.10.4 §4.4 将东财 `RPT_SHAREBONUS_DET` 的原始 JSON 保存为 `<带市场前缀的代码>.json`，并给 freeze 传入 `--candidates <私有候选目录>`。候选只筛选缺事件日期的实施记录，保留原始响应和字段，状态为待裁决。不得据通用辅助函数的单位注释直接变更旧派息账本。
- 原证券组合、50 万元初始资金、90/10 仓位、周股息率分位、KDJ、陕鼓动力价格区间、银行校准及 `cash_then_sell` 按旧路径执行。股息与税费复投规则由同一旧模拟器执行。固定历史组合及分红可用性未做 PIT 证明。

## 历史余额口径

`legacy_book_balance` 是历史模型未投资账面余额，包含模型按除权日计入的股息。它只用于还原旧看板和核对权益。结果的 `settled_cash_available` 为 `null`，因为输入没有独立到账流水，无法区分已到账现金与应收。该结果不能用于可用资金判断。相同快照按其冻结适配器回放，当前适配器输出使用新版本口径。

## 验收对应

| 要求 | 证据 |
|---|---|
| 原组合、环境、配置、预热、版本 | 私有清单及固定源码副本 |
| 固定输入、冲突、预热不足及候选记录 | freeze、私有缺口记录、合成测试 |
| 看板对拍 | 按日期精确匹配，NAV 和收益率绝对容差 `1e-7`，人民币绝对容差 `0.00500001`。比较逐日 NAV、净股息和可用汇总 |
| 研究导出对照 | 同策略同起点重叠区间的逐日值、校准日期及状态、可用费用和股息税。结果单独标记 |
| 逐笔费用与持仓 | 旧模拟器明细及独立逐日旧模型账面余额、持股市值与净值核对，人民币绝对容差 `1e-6`。历史参考缺逐笔成交和每日持股数量，固定看板版本也无逐日现金及持仓估值字段 |
