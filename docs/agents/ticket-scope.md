# 票据范围与 Prepare

本文件是 `to-tickets`、`implement-ticket`、`ticket-loop` 与独立 review 的范围/规模/权限裁决权威。验收以原 Issue/spec、父 Spec 必需行为及负责人明确裁决为准；不能为适配实现缩减。

## 先判契约，再看规模

一票交付一项可独立验收的行为或契约。独立契约有自己的输入、结果及失败语义，能单独验收，并有独立使用者或交付价值。同一行为的页面、HTTP、CLI、存储适配可以属于一个薄纵向切片；接口数量、文件数量和跨层本身不构成拆票理由。

共享浏览器框架等基础能力可以独立成票：明确使用者、复用边界及可运行的验收路径，无需为每票增加新 UI。产品票仍须覆盖自己承诺的生产闭环；基础能力完成不表示产品验收完成。

规模统一用相对票据固定基线的新增行 + 删除行，分列**主要实现、手写测试（含 fixture/E2E）、辅助文档、生成文件、Unknown/待核实**，保留合计、估算区间及实际量。主要实现是本票的实际交付逻辑：纯文档/Skill 票的文档即主要实现；测试目录内的执行器、复杂框架或独立业务核心仍须识别契约并计入主要实现。测试路径只提供分类线索，不构成豁免。Rust 内嵌 `cfg(test)` 等按内容分类，无法可靠识别时标待核实，不靠文件名强行分配。生成文件注明来源；所有分类照常审查，不靠删测试、压缩代码或延后验证达标。

**800 行按主要实现计量**，仅触发范围/可审查性复核。记录独立契约、分类实际量/新估算、验收覆盖与审查安排。未知内容可能影响提醒点时先按保守上界复核。低于它仍需识别独立契约，超过它本身不要求暂停、预算例外或拆票。

**首次估算上沿两倍或总 changed lines 2000 行，任一先到**，触发强化可审查性复核。保留首次基准，不滚动上调掩盖增长；说明增长是需求还是同契约必要测试/有效修复，给出分类量、跨模块风险、覆盖、分段阅读入口及可执行审查安排。有明确安排且符合下方权限时继续，无法保障审查容量才升级裁决。提醒点不是无限增长授权，硬预算继续约束总量。

普通估算用于计划，既不是承诺也不自动成为硬预算。硬预算必须由负责人明确指定固定范围和总量，例如：`硬预算：<固定范围>；相对 <base SHA> 新增+删除合计上限 N 行（含所有分类）`。既有仍有效明确总上限按原授权执行，不能仅因未使用新格式将其降为估算。

## 首次范围检查

`to-tickets` 为当前无 blocker 或紧接当前前置、计划近期实施的票保留完整六项证据。能引用已读证据就复用，检查到足以判断缺口、验收路径和估算即可；不预先完成整票设计。

```text
交付：一个可观察行为（或基础能力的使用者与可验收结果）
现状：已有生产入口、实际缺口及代码/测试证据；注明基线
边界：几个独立契约，分别是什么；同一行为的跨层适配说明关系
验证：生产入口 → 持久结果 → 可观察输出，必要正常/失败/边界场景
规模：主要实现 / 手写测试 / 辅助文档 / 生成文件 / 待核实区间、合计与估算依据
结论：继续 / 申请负责人裁决 / 按契约提议拆分，给理由或授权引用
```

只读或基础能力不适用持久化时，说明原因及可观察产物，不额外制造存储要求。接口、schema 或量化口径所需文档及 ADR 计入估算。

远期票只保留行为/边界/依赖，标记范围检查待补。缺检查、口径未定或待负责人决定用 `needs-triage`；证据及决定齐备后才用 `ready-for-agent`，实际认领仍须无 blocker。

## 增量 Prepare

已有首次记录时，引用该记录/授权与原基线，固定最新 main，只发布以下三项，不重写完整六项：

```text
Scope Delta：当前基线与原记录差异；入口/前置/契约/验收/估算变化，或明确无变化
Verification：验收映射与关键反例的新增/受影响场景、命令及证据计划；未变项引用原记录
Decision：按权限规则继续或请求裁决，引用仍适用的授权及首次获批估算
```

旧票缺首次检查时补齐六项；基线实质变化时补齐受影响项证据并说明未变项依据。既有完整记录继续可引用。原 Issue/spec 与父 Spec 必需行为都进入 Acceptance Mapping，不能只映射缩写后的 checklist。

## 继续与暂停权限

下列条件同时满足时默认继续：同一已批准行为/契约、验收及权限未扩大、具备可审查安排、未突破仍有效的票内硬预算。包括同范围估算偏差、必要测试和有效 Review 修复；更新增量证据即可，不重复请求许可。

出现以下任一情况，暂停受影响工作，在本 Issue 只记录新增事实并申请负责人决定：

- 新增独立交付契约，或需要调整原验收、权限、量化口径；前置需求存在歧义。
- 需求存在实质歧义，或强化复核后仍无法保障阅读/审查容量。
- 预计突破仍有效的票内明确硬预算或尚未迁移的特殊条款。

同范围估算偏差、必要测试和有效 Review 修复默认继续，提醒点更新复核证据即可；权限/契约变化与单纯规模变化分别说明。已有固定范围授权在其硬预算内直接复用；突破硬预算须裁决，不用本规则自行扩大授权。首次发现遗漏时解释前置检查漏项。

需要拆分时，给出各子票行为/契约、估算、依赖及原验收逐项去向，等待负责人确认后调整票据。待裁决时将已认领票改为 `needs-triage`、移除自己的 assignment，按 [tracker](issue-tracker.md) 保全工作区；获批后恢复 `ready-for-agent`，重新核对资格再认领。授权不豁免验收、必需验证或独立 review。

## 旧票迁移

开放票中的明确硬预算或“超 800 必须拆”等特殊条款继续有效，除非负责人在**对应 Issue** 明确批准迁移。提出新规则引用与具体替代决定，不能静默取消旧限制。已完成票、历史验收与既有拆分不追改；旧票缺检查只在下次 Prepare 补齐，不重新调查无关历史。

迁移清单及原条款/替代授权见 [#371 集中裁决](https://github.com/ZombieIce/PrajnaQuant/issues/371#issuecomment-6541421370)：仅 #302、#304、#305、#309–#318，逐票留原文及授权引用。#301 已完成、#286 历史拆分不追改。新增待迁移票须重新列出并获负责人批准，不能从这份有限清单推定全仓库授权。

机械统计入口及分类局限见 [工作流辅助工具](workflow-tools.md)。工具不给契约/权限裁决，也不替代完整测试与 Review。
