# Universe 功能设计与多 Agent 实施方案（提案）

状态：**Proposed，部分契约已冻结**。产品/实施细节以新增 `docs/universe-contract.md` 为冻结契约；本文件后续实现描述可能与契约冲突，冲突时以契约为准。现状以代码、测试及 `docs/STATUS.md` 为准。此提案不将沪深300指数行情误认为沪深300历史成分，也不将今日自选证券集合称为无幸存者偏差的历史 universe。

## 1. 目标与当前边界

- 用户可管理多个命名 universe：名称、简介、资产范围、来源、版本、成员和历史覆盖；可按证券交易所与代码加入股票或单只 ETF。
- 可选择有可信历史成分数据的指数 universe，例如沪深300，并按每个历史决策时点解析成员。指数权重可保存为来源事实，但**成分筛选不等于按指数权重建仓**。
- 策略回测与因子评价显式选择一个 universe 的不可变版本；策略/因子列表能按该版本筛选已保存结果。网页发起新运行是独立能力，不能把“筛选报告”冒充“重跑”。
- 当前 `sql/schema.sql` 没有历史指数成分；`research.etf_daily_bar` 按当前 ETF 分类回填历史。`data.rs` 只导出 ETF 行情及沪深300基准价格；`core.rs::ExperimentConfig` 无 universe；`server.rs` 只有只读 GET；React 无 universe 页面。
- 沪深300历史成分是**股票**。先实现历史成分数据和解析，不代表已有 ETF-only 快照、费用、手数、停牌/公司行动规则适用于股票。股票回测支持须独立验证；未完成前 API/前端拒绝以股票池运行 ETF Rotation。

## 2. 产品语义

一个 universe 定义有稳定 `universe_id`、可编辑的 `name`/`description`、`asset_scope`（stock/ETF/mixed）、`source_kind`（manual/index）、状态（draft/published/archived）和不可变 `version_id`。已发布版本不可原地改成员；编辑产生草稿，发布产生新版本。归档只阻止新运行，不删除历史实验所依赖的版本。

| 来源 | 成员规则 | 历史声明 |
| --- | --- | --- |
| 手工集合 | 用户以 `exchange + code` 加入股票/ETF，去重并核验证券身份；可设成员生效区间 | 今天创建的名单用于往年回测，标记 `retrospective_static`；不声称历史无偏 |
| 指数历史成分 | 从带来源和覆盖证明的历史截面/调整事件解析 `effective_from <= T < effective_to` 的成员 | 只有公告可知时点和历史覆盖均经验证，才标记 `verified_pit`；缺口标记 `unknown`，严格模式拒绝运行 |

首版只支持手工集合和指数历史成分。若将来需要“沪深300 + 手工加入/排除 ETF”，以版本化覆盖规则扩展，不把手工改写混入官方指数原始成分表。

`membership`、`eligibility`、`tradability` 必须分开：前者表示 T 日属于所选集合；后两者分别表示策略允许参与评分、下一开盘可以真实成交。没有行情或停牌不是“已从指数剔除”。持仓出池后仍保留所需行情，用于估值与卖出；缺行情时沿用仓库已明确的成交/估值政策并暴露未完成交易，不能直接删除持仓。

## 3. 数据与版本模型

### 来源事实（DuckDB 仓库）

建议增加可回放的 schema 升级，而非仅编辑 `CREATE TABLE IF NOT EXISTS`：

- `core.index_membership_revision`：`index_id`、`instrument_id`、`effective_from`、`effective_to`（半开区间）、`published_at`/`known_at`、`source_id`、`source_ref`、`source_snapshot_id`、可选 `weight`、`observed_at`、`revision_hash`。`observed_at` 是本机采集时间，不能代替当时公告时间。
- 来源快照/覆盖记录：指数、交易日或调整期、是否**完整截面**、证券数量、文件 hash、原始 URL/公告、覆盖起止日、导入时间与校验结果。只有完整截面或明确剔除公告才能推断成员退出；某次抓取缺行不能推断退出。
- 证券身份使用稳定 `instrument_id`，保留交易所、交易代码和名称修订；上市/终止上市日期与指数成分日期分开保存和核验。历史指数成分数据未到位时不得用 `index_constituents()` 的最新快照反向填充。
- 当前本机 `a-stock-data` skill 的 `index_constituents("000300")` 契约是**最近发布的快照**，并非完整历史成分接口。沪深300历史回测的首个数据门槛是取得、授权使用并校验覆盖目标区间的历史调样/成员资料；未取得前只开放管理与展示，不开放“历史沪深300成分回测成功”的状态。

### 用户配置与运行产物

- 小型用户配置可先由现有 Rust 服务管理为原子写入的版本化 JSON 目录；指数来源事实仍以 DuckDB 为权威。若选择写入 DuckDB，则先明确仓库单写者与服务写入如何串行，不能让只读 `serve` 偷变成并发写者。两种存储方案由契约阶段定案，避免各 Agent 自行决定。
- 每个发布版本保存定义、手工成员及生效区间、来源引用、创建时间、内容 hash、资产范围和 PIT 等级。删除草稿可物理删除；已发布版本仅归档。
- 每次运行冻结：`universe_id`、`version_id`、定义 hash、历史成分来源版本、解析后日期×证券成员 hash、覆盖/缺口、PIT 等级、行情快照 hash、引擎版本。旧实验不受后来编辑和来源修订影响。
- 可选缓存是加速层，键至少包含 universe 版本/来源 hash、日期范围、决策时点口径；不得把不同 universe 的因子/评分结果混用。

## 4. 时间与计算规则

沿用当前回测时序：T 日完整收盘数据产生信号，T 收盘后决策，下一有行情日开盘尝试成交。T 日候选应满足当时已生效且已公开的成员规则；只有日期、没有可靠公告时刻时，采用保守可知边界并记录假设。**未来才公布的调整不可用于过去的信号**。指数提前公告但尚未生效的新成员也不应提前进入当前成分；是否允许“预调仓策略”是另一种策略规则。

市场数据加载保留足够的入池前历史，供 rolling 因子预热；保留出池后的行情，供旧仓估值/卖出和因子未来标签。成员掩码只在 T 日策略候选、横截面归一化/排名、因子评价观察样本处应用；不能先按逐日成员剪掉整个价格面板。因子未来收益是评价标签，不能回流成员解析或策略评分。

动态成员为空时须明确选择“产生空目标并尝试清仓”或“暂停调仓并保留仓位”，同时覆盖暂停/缺行情；不得沿用当前 `backtest.rs` 的非空目标门槛而静默保仓。指数退出、上市/终止上市、缺执行 bar、停牌、最后一天 pending 均需可人工验算。

ETF 与股票可共用成员解析接口，但**运行能力分级**：`membership_ready`、`factor_research_ready`、`strategy_backtest_ready`。股票策略运行需要股票行情快照、交易单位/费用/状态/公司行动口径和测试通过后才开放。UI 以真实能力状态禁用运行并解释原因。

## 5. API 与页面契约（均为计划，不是现有路由）

新路由统一置于 `/api/v1`；保持现有实验 GET 路由兼容。请求/响应与错误码由接口契约 Agent 先冻结。

| API | 用途 |
| --- | --- |
| `GET /api/v1/universes`、`POST /api/v1/universes` | 列表分页/搜索/资产范围/状态；创建草稿 |
| `GET /api/v1/universes/{id}`、`PATCH /api/v1/universes/{id}/draft` | 详情、编辑草稿；成员新增/移除属于草稿变更 |
| `POST /api/v1/universes/{id}/versions`、`DELETE /api/v1/universes/{id}` | 发布不可变版本；归档已发布 universe（不级联删除结果） |
| `GET /api/v1/universes/{id}/members?version_id=…&as_of=…` | 指定 T 日成员、来源、完整性、PIT 等级和警告；日期必填 |
| `GET /api/v1/universes/{id}/coverage?version_id=…` | 历史覆盖范围、缺口、可运行能力与数据来源 |
| `GET /api/experiments?universe_id=…&version_id=…` | 筛选已有策略实验，保留未筛选旧行为 |
| `GET /api/v1/factor-reports?signal_key=…&universe_id=…&version_id=…` | 筛选因子报告；替代“每个 signal 仅取最新 report”在多 universe 下的歧义 |
| `POST /api/v1/runs`、`GET /api/v1/runs/{id}` | 选择 universe 及策略/因子参数发起异步运行、查看状态；只有运行服务与并发/取消/持久化政策完成后开放 |

前端 `/universes` 提供列表、创建、编辑、归档；详情展示简介、版本、类型、资产范围、指定日期成分、成员数、来源、覆盖缺口和 PIT 警示。策略与因子页面分别提供两种操作：按 universe 筛选**已保存结果**；在可运行能力允许时选择 universe 版本并**发起新运行**。运行详情固定显示当时使用的版本/hash/覆盖；名称后改不改变历史结果。前端不自行推导历史成分、评分或绩效。

现有 `server.rs` 只有六个只读 GET，CORS 宽松且无身份认证。写接口仅限本机可信使用，或在开放网络前增加鉴权、来源检查和写入保护；不能把现有服务直接公开供写入。

## 6. 并行协作安排

先由整合 Agent 冻结 `docs/universe-contract.md`：ID/版本、半开时间区间、PIT 等级、成员查询、报告字段、错误码、旧实验兼容、数据存储选择与空池行为。实施 Agent 在契约冻结后按波次并行，独占文件/目录，跨边界变更先向整合 Agent 提议。不要让多个 Agent 同时编辑 `backtest.rs`、`docs/STATUS.md` 或 `HANDOFF.md`；当前工作树已有其他任务的未提交修改，启动时先 `git status`。

| Agent | 独占范围与交付 | 依赖/不得越界 |
| --- | --- | --- |
| A：历史数据 | `sql/`、`src/` 内 schema 升级、指数成分导入与来源校验；小型完整/缺失截面 fixture | 不修改回测算法；不能以最新成分伪造历史；数据覆盖不足时明确失败 |
| B：Rust 计算 | `crates/quant-research/src/` 的共享模型、成员解析、快照/配置/实验/因子/策略接入；动态池金标准测试 | `server.rs` 留给 C；当前其他任务正在改 `backtest.rs`，先等其合并/交接或在隔离分支集成；股票运行能力未验证前保持阻断 |
| C：API 与运行 | `server.rs` 与独立 universe 配置存储模块；CRUD、成员/覆盖、结果筛选及异步运行状态 | 依赖 A/B 冻结的模型；不自行实现另一套成员解析；写接口安全边界明确 |
| D：React | `apps/web/src/` 管理页面、成员日期查看、结果筛选、运行选择及能力/风险提示 | 使用冻结的 API 契约和 mock 数据开发；服务未支持时不展示“可运行”状态 |
| 整合 Agent | 契约、跨模块测试、文档与 ADR、分支合并、`STATUS`/`HANDOFF` | 最终唯一负责解决文件冲突及发布验收；不把计划记成已完成 |

当前会话最多四个并发 Agent（含整合 Agent）。推荐波次：① 整合 Agent 冻结契约与固定 fixture；② 整合 Agent + A/B/D 并行，D 使用 mock 契约；③ A 或 B 交付模型后启动 C，并由整合 Agent 接线；④ 股票回测能力门槛；⑤ 网页异步运行。若资源有限，先交付 ETF 手工 universe 的端到端最小切片，同时保留历史指数数据模型和“沪深300尚不可运行”的明确状态；不得把这一步报告为用户需求全部完成。

可复制的任务委派要点（每个 Agent 均先按 `AGENTS.md` 阅读仓库、查看 `git status`，在独立分支/工作区工作；只提交其独占文件）：

- **A**：“依据 `docs/universe-design.md` 和冻结的 `docs/universe-contract.md`，实现可回放 schema 升级、历史指数成分来源表/覆盖校验和 3 证券 fixture。保留公告时间、生效时间、来源 hash；不以当前成分填历史；只改 `sql/`、仓库写入侧 `src/` 及其测试。提交数据契约、覆盖缺口和测试结果。”
- **B**：“依据同一契约实现 Rust universe 解析、实验配置/报告引用、因子观察样本及策略候选掩码，保留入池前和出池后行情。先与已有 `backtest.rs` 未提交工作协调；只改 `crates/quant-research/src/` 中除 `server.rs` 外的计算文件及测试。股票交易未验证前返回能力错误；提交手算 PIT/动态池测试与缓存隔离结果。”
- **C**：“依据同一契约实现版本化用户配置存储、universe CRUD/成员/覆盖/报告筛选 API，并在计算入口就绪后接异步运行；独占 `server.rs` 和新 API/存储模块。保留旧 GET 兼容；写接口限制本机可信使用；提交路由契约测试和旧实验兼容结果。”
- **D**：“依据同一契约和 mock 响应实现 React universe 管理、指定日期成员展示、策略/因子结果筛选及选择版本发起运行的 UI；独占 `apps/web/src/`。明确区分已保存报告筛选与新运行，展示 PIT/覆盖/能力警示；提交构建和交互验证。”

## 7. 验收门槛

1. 固定 3 证券/10 交易日样例含：手工加入股票与 ETF、指数成员加入/剔除、公告早于及晚于生效、上市前/退市后、空候选、缺行情、入池前因子预热、出池后旧仓估值/卖出。期望成员、信号、订单、现金、数量及 NAV 由独立手算表给出。
2. 同一历史 T 日不受今天的成员、名称或版本变更影响；未知/不完整历史区间在严格 PIT 模式拒绝，不能默默沿用今天快照。保存结果可追溯到版本与内容 hash。
3. 策略与因子都在同一 T 日成员掩码上评价；未来标签不进入评分；不同 universe 的缓存与报告不会串用。动态空池与不可交易仓位遵守已批准的事件模型。
4. CRUD、归档、分页和错误校验通过；旧实验仍可读取并明确显示 `legacy_universe_unknown`，不会伪造版本。页面区分筛选旧结果与提交新运行。
5. ETF/股票费用、手数、分红/折算和可交易状态分别验收；股票池若尚不能正确交易，运行请求返回明确能力错误。通过 `cargo fmt --all -- --check`、相关 `cargo test`/`clippy` 与 `apps/web` 构建，并更新 `docs/STATUS.md`、`HANDOFF.md`、API/时间/数据文档及必要 ADR。
