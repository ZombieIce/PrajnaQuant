# MVP-6 未决门禁的裁决选项（#199）

本文件是 [#199](https://github.com/ZombieIce/PrajnaQuant/issues/199) 对 [#171 P26](https://github.com/ZombieIce/PrajnaQuant/issues/171) 的提案，**不是 spec 修订或开工许可**。P26 的权威文本以 #171 的负责人评论为准。采集与公开边界沿用 [#172 授权决定](https://github.com/ZombieIce/PrajnaQuant/issues/172#issuecomment-6189539822)。

## 结论与证据边界

P5、P7、P8、P9、P10、P11、P12、P21 均为 `unresolved`；P9 的本轮结论替代补证前的 `defer` 表述，但不修改其他票据的历史结论。**#194 开工门禁未通过**。补证审计的完成不等于真实数据验收通过。

公开内容只包含上述文字结论、取证方法和待裁决的契约选项。Raw、请求日志、网络路径、hash、覆盖计数、样本归因、规则材料与审计明细均仅存本机 `~/PrajnaData/mvp-6/`。本票私有交接索引位于 `acceptance/issue-199-index-*.json`，指向逐阶段档案、私有交接说明与离线重放入口。公开文档不提供真实数据示例或证据摘录。

本轮复用既有 Raw 与 #190 本机审计，并补查官方查询筛选和相同来源、相同样本窗口的双源数据。公告查询的深市基金筛选、全集分页和附件覆盖未建立可核验证明，因此不能用空查询代替公告全集，不能完成历史名录双向差异闭环、逐日 PIT 属性映射或公司行动全集与价格异常的完整交叉核验。双源差异的单位/来源修订归因仍未闭环；经验倍率不构成单位证明。源站域名不同也不构成上游独立性证明。

本机价格异常诊断与离线对拍重放是审计辅助：它们不能证明公告完整性、PIT Universe、开盘可成交性、总回报完整性或真实业绩。本轮没有发布 Dataset Version 或运行真实验收账本。未建立真实数据独立校验结论。

## 负责人如何裁决

以下每项提供 A、B 两个具体选项。**推荐 A；推荐不等于选择。** A 保留现有证据门槛，具体规定下一轮补证交付；B 是负责人可考虑的显式工程验收契约修订，不能沿用原 P0 已解决或完整历史业绩的表述。负责人需在 #171 逐项回复所选项；未裁决时现有 spec 继续有效。

所有选项均保留原数据/决策窗口、TDX/腾讯/cninfo 来源和逐 tick、整数份完全比较规则；不使用百分比误差。B 所提的证据范围变化也必须由负责人明确批准。即使某项选择 B，也不自动解除其他门禁；需有连贯的修订后 spec 和机器可判定验收条件，才能重新判断 #194 是否可开工。

### P5：官方公告来源覆盖 — unresolved

- **A（推荐）：保留全集门槛，增加公告检索验收协议。** 从官方检索界面确认深市基金参数和目录身份，以正向、反向筛选控制核实语义；按日期分片全分页，核对声明总数、唯一公告 ID、重复/重叠边界和附件。覆盖上市、合同/招募、类别/指数变更、终止、分红、折算、停复牌，并补窗口前已上市产品的起始文件。Universe 仍须历史全集；状态仍依赖可核验公告覆盖；收益仍按 6a/6b 原口径；任一覆盖缺口继续阻断声明范围运行。查询不可验证时保留 unresolved，不要求负责人代替 agent 取证。
- **B：将当前工程验收限定为“缺覆盖即拒绝”的失败路径验收。** Universe 不发布为历史全集，状态保留 UNKNOWN；不生成成功价格收益或总回报结果；缺覆盖导致整个声明窗口报错，并验收错误定位、来源追溯及拒绝发布行为。若批准，需在 #171 明确这不能完成原 MVP-6 真实验收，也不能单独解除 #194 的其他依赖。

### P7：历史名录与代码复用 — unresolved

- **A（推荐）：保留历史全集，要求逐生命周期对账表。** 将完整 cninfo 上市/终止目录与 159000～159999 扫描双向连接；每个差异必须有官方生命周期证据或未决原因，同代码分期映射独立 InstrumentId。Universe 不因行情缺失删成员；状态不由首末行情日推断；收益不得跨生命周期拼接；名录完整性或复用归属未决则整个声明范围报错。
- **B：新增“已验证生命周期集合”的工程数据集类型。** Universe 明确改为人工可审计、版本化的已证实集合，附未知生命周期隔离清单，禁止声称历史深市全集或无选择偏差；状态仍逐格取证；收益仅作该集合的工程结果，6a 不解释为业绩，6b 也不能冒充原范围总回报验收；隔离行禁止参与连接，集合内缺覆盖仍报错。此方案改变 Universe 声明，必须显式修订 P7/P8 及相关验收，不能静默删未知成员。

### P8：日期级类别与标的指数 — unresolved

- **A（推荐）：保留 PIT 定义，补齐双时态属性链。** 从起始合同/招募、上市及变更公告提取类别、指数、生效区间和可知时刻；冲突单列，不将今日类别回填历史。Universe 仅按当时已知属性筛选，全集完整性另验；状态仍独立取证；收益输入不含未来分类；无法证明声明范围成员完整性时运行失败，不能只排除未知属性后签字。
- **B：仅在 P7-B 同时获批时采用“属性证实区间”。** Universe 声明缩为已验证生命周期与已知属性区间的交集，按版本列出排除原因；状态门禁保留；输出只标工程结果和选择偏差限制，不完成原历史全集收益验收；未知区间不进入 Eligible Set，若已持仓需退出仍按原延期规则处理。不得通过名称关键词补分类。

### P10：开盘执行状态 — unresolved

- **A（推荐）：保留公告全集排除法与双源联合门槛。** 为每个 Instrument/Session 建停复牌公告生效时段、可用时刻、双源对拍及规则证据连接；盘中复牌或有量不直接证明开盘可成交。Universe 成员身份不随状态删除；状态只按 P10 三态与方向门禁推导；收益仅使用获准成交；持仓退出 UNKNOWN 时整次调仓延期，全市场 Session/声明范围覆盖缺失仍报错。
- **B：改用更窄的“官方明确开盘时段证据”放行集合。** 无法证明公告全集时，不用“未搜到停牌”放行；仅官方文件明确覆盖开盘可交易时段、且双源和规则均通过的格子可进入 TRADABLE。Universe 保留成员，其他格子 UNKNOWN；收益仍严格使用可执行格子并披露工程限制；未知持仓退出延期，覆盖不完整的声明窗口仍失败。该选项可能不产生可验收成功运行，不能用全 UNKNOWN 的零成交代替通过。

### P11：双源完全一致与来源独立性 — unresolved

- **A（推荐）：保留必需样本全通过门槛，补单位与修订链。** 对每个失败格子记录原始字段、单位依据、tick 编码、整数份检查及供应商修订身份；补采同源同窗口后从冻结 Raw 重算。来源错误或修订不能靠倍率猜测归因，并另证实上游独立性。Universe 不因差异删成员；差异/缺失状态 UNKNOWN；收益不使用未通过的成交；原必需样本和覆盖证明未完成则门禁继续关闭。
- **B：将样本门禁修订为“差异定位并隔离”，保留逐格完全一致的成交门槛。** 不修改价格或成交量，不容忍数值差异；Universe 保留冲突成员，冲突格子 UNKNOWN，双方均通过且来源独立性有证据的格子才可放行。收益只作修订后的工程口径；已持仓冲突仍整次延期，整体覆盖失败仍报错。需明确修改“必需样本全部通过”的开工要求；不满足必需控制样本时仍不能宣称原真实验收通过。

### P12：PIT 规则类别、首日和参考价 — unresolved

- **A（推荐）：保留逐日适用性证明。** 官方条文须有文号、生效/废止区间、基金类别映射、tick/舍入、首日例外与除权除息参考价证据；结合 P8 历史属性逐格归属。Universe 不由当前规则倒推；规则未知则状态 UNKNOWN；收益仍使用原始成交价和正确方向门禁；持仓退出规则未明时延期，声明覆盖失败继续报错。
- **B：把规则未知格子专列为不可执行工程用例。** Universe 保留成员，不猜 10%/20% 或首日豁免；未知格子 UNKNOWN，拒绝买卖，并验证 pending 和陈旧估值语义；收益仅是规则已知范围的工程诊断，不声称完成完整真实窗口验收；全市场/声明覆盖不完整仍失败。若目标是成功运行，仍需 A 的证据，不能以该失败路径验收替代。

### P21：公司行动完整性与价格不连续交叉核验 — unresolved

- **A（推荐）：保留 6b 完整性门槛，补事件与价格的双向连接。** 对每个 ETF 核验分红/折算/终止/清算公告全分页及附件；逐事件核对价格/参考价变化，同时逐异常反查公告，记录漏检能力边界，不能把低于报警阈值视为无分红。Universe 沿用 P7/P8；事件或参考价冲突进入 UNKNOWN；收益只在完整性成立后称总回报；疑似未解释除权除息报错或 UNKNOWN，未知清算金额标不完整，不能删持仓。
- **B：明确仅验收“不完整公司行动输入”的拒绝路径。** Universe 不变，未解释异常仍 UNKNOWN/报错；允许本机保存不完整诊断，但禁止完整 TRI、总回报业绩和 6b 成功声明；账本不能忽略应收/折算/清算。原 6b 门槛保持待办；6a 是否可做价格收益工程验收须单独满足其余门禁，不能据此批准原 #194。

### P9：Eligible Set — unresolved（上游决定后再评估）

- **A（推荐）：上游证据全部通过后按原条件重算。** Universe 与 Eligible Set 分离，保留 61/60/20 Session 边界及原流动性阈值；HALTED 成交额计零，UNKNOWN 不补零。状态和收益沿用原执行语义；全市场/声明窗口覆盖缺失报错，证据完整时空合格池才允许持现金。
- **B：仅在上游范围修订获得批准后做显式工程模式。** Eligible Set 的阈值和时间规则不变，但输入 Universe 必须标出批准后的有限证据契约；UNKNOWN 仍不合格，不能把“不在合格池”变成可卖许可；只输出对应范围的工程诊断，不声称原 P0 或业绩验收；集合内覆盖不足仍报错。需将模式与原历史全集验收分开，禁止静默降级。
